# 再生のつなぎ方と音量調整

## 操作

メニューの「再生設定」でフェードイン、一時停止・停止時のフェードアウト、曲間クロスフェードを個別に有効・無効へ切り替える。それぞれ1〜12秒の整数で指定できる。初期値はフェードイン3秒、フェードアウト3秒、クロスフェード5秒で、いずれも有効。拡大プレイヤーの停止ボタンも同じフェードアウトを使う。途中で再開した場合は現在の音量から戻す。

ピーク音量ノーマライザーの初期値は無効、Automixの初期値は有効。設定は端末ごとに保存され、再ログインは不要。保存に失敗した場合は現在の入力を維持して再試行を表示する。

スリープタイマーのフェード時間にもフェードアウトの秒数を使う。タイマーは消灯前に減衰する仕様のため、通常停止用の有効・無効とは別に適用する。ヘッドホンの切断や音声フォーカスの喪失では、OSと接続状態に従って即座に止める。

## 音声エンジン

MediaSessionには`TransitionPlayer`を接続し、Android標準DRMを使う2つのExoPlayerを制御する。次の曲を事前準備し、実際にデコード・再生できる状態になってから重ねる。再生待ちの通信やバッファリング時間をフェード時間へ数えず、音声の再生位置が進んだ時間でゲインを更新する。

2つの線形ゲインの和を1にし、同じ波形が重なっても過大な出力にならないようにする。短い曲は前後の曲の半分を上限として重なりを短くする。次の曲が準備できなかった場合は、無音の次曲を前提に現在の曲を消さず通常の曲送りへ戻す。

次・前・新しい選曲、シーク、リピート、シャッフル、通知の再生操作は同じトランスポートを通る。2つのデコーダーの音声フォーカスを1つにまとめ、一方の破棄で他方の音声フォーカスを失わない。Android 15以降のバックグラウンド再開では、前景サービスの通知更新が完了してから音声フォーカスを要求する。待機中にキャンセル・別操作が入った場合は、古い完了が新しい待機を消さないよう世代を照合する。選曲の置き換えに続く重複した再生要求は、重なりがゲインを持っている間は両デコーダーを消音せずフェードも作り直さない。

## ピーク音量ノーマライザー

これはLUFSに基づくラウドネス正規化ではなく、復号後PCM16のストリーミング・ピーク正規化である。再生中に観測した最大ピークを保持し、−1dBFSを目標に左右共通のゲインを適用する。増幅は最大+12dB、−60dBFS未満の信号は持ち上げない。増幅は時定数2秒で滑らかに変化させ、新しいピークを観測した場合の減衰は即座に行う。シーク・曲変更・flushで履歴を初期化する。

処理はEQの後へ接続する。音声スレッドはimmutableな設定スナップショットだけを読み、設定保存や認証通信を行わない。PCM、音声鍵、ライセンス本文は保存しない。

## Automix

サービスの拡張メタデータでプレイリストの対象判定と曲のcuepointを取得する。通常のクロスフェードと同一処理を別名で表示する方式ではない。対象の曲が現在のプレイリスト原本に含まれること、応答URIと型、前後の曲の対応を検査する。

確認済みの対象モードだけで、提供された退場・入場位置を使用する。信頼度0.9以上、40〜240 BPMのcuepointを使い、前後のテンポ差が10%以内なら入場曲を時間伸縮して合わせる。重なりの終了後は通常の速度に戻す。時間はクロスフェードの設定以下になるよう拍長へ丸めるが、1秒の下限を優先する。

実ファイルの残りが設定時間より短い場合は、cuepointとテンポを維持して残区間へ短縮する。端末の制御が少し遅れた場合も、まだ1秒以上の区間が残れば入場位置をテンポ比に応じて進め、同じ終了位置へつなぐ。遅延を一律100msで対象外としない。曲の範囲外や残り1秒未満は通常の遷移へ戻す。

対象外・cuepoint未提供・確かな組み合わせがない場合は通常のクロスフェード設定を使う。通信失敗や型・URIの不一致を、対象外の成功応答と取り違えない。新しい個人用ミックス編集機能の独自プリセットや編集機能まで再現したと扱わない。具体的な契約と原本の確認先は[API契約](api-contracts.md)を参照する。

## 検証

- `PlaybackTransitionSettingsTest`、`PeakNormalizerTest`、`AutomixMetadataTest`、`AutomixApiClientTest`：秒数境界、音量包絡、PCMピーク、実応答のcuepoint、対象・所属・アカウント・キャッシュ・型の検査。
- `PlaybackSettingsScreenTest`、`PlaybackTransitionStoreTest`、`PeakNormalizerAudioProcessorTest`：画面の全設定、保存・再構築・破損・保存失敗、実PCM processorの接続。
- `PlaybackTransitionsTest`、`PlaybackTransitionFailureTest`：2曲同時再生、通知相当の操作、待機中の中断、バックグラウンド再開、エラー時の有効な状態、両デコーダー停止。選曲置き換え直後に両デコーダーが消音されないことも検査する。
- 実機は`LiveAutomixAccountTest`に`liveAutomix=true`、`LivePlaybackTransitionsTest`に`liveTransitions=true`を指定する。後者は実際に音を出す。Automixの音声検査では`automixPlaylistUri`と、必要ならその原本に含まれる`automixFromUri`・`automixToUri`を両方指定する。未指定なら先頭2曲を使う。

実音声の検査は2つのデコーダーそれぞれのDSP後PCMのRMS・ピークと最終ゲインを読む。`StreamMetadata.positionOffsetUs`から媒体時刻を付けた100msの数値窓を保持し、現在の再生位置と同じperiod・generationの窓を使う。EOSは端末へ渡した音声が鳴り終わったことを意味しないため窓を消さず、シーク・新ストリームで分離する。実検証音源ではencoderDelay/encoderPaddingが0であることも確認する。波形を保持したり、単なる計測時刻の新しさを音声の有無として扱ったりしない。

30秒以降の音声、重なり中に両方が非無音であること、入場位置・速度、停止を検査する。端末全体の音量を変えず、テスト後に再生設定とEQを復元する。マイクによる録音や音声データの保存は行わない。
